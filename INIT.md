# Initialise this domain repo

You're reading this because the repo was just generated from
`gcp-data-domain-template`. Run `init.sh` once, then delete nothing by hand —
it removes itself and this file when it's done.

```bash
./init.sh \
  --project datacloud-foo \        # GCP project id (single source of truth)
  --repo    datacloud-foo-analysis \   # this repo's name
  --org     gCloud-Tech-Showcase \ # the GitHub org this repo lives in
  --slug    foo-analysis \         # short label, used in resource labels
  --title   "Foo Analysis" \       # human-readable, used in docs/descriptions
  --domain  foo_analysis \         # Dataform tag for this domain
  --unstructured \                 # ONLY if the domain needs GCS + BigLake + Gemini
  --private                        # ONLY if this GitHub repo is private
```

## Is this repo private?

Then pass `--private`, and make sure it matches reality — the two git-link
paths share no code:

- **Public** — Dataform pulls over an *anonymous, tokenless* link. No
  credential exists anywhere.
- **Private** — Dataform pulls over SSH with a **read-only deploy key**.
  `setup.sh` generates the key, puts the private half in Secret Manager and
  registers the public half on this repo, so there's nothing to create by hand.
  It needs [`gh`](https://cli.github.com) authenticated against this repo.

The key is deliberately *not* generated by Terraform: the provider only ever
takes a Secret Manager version name, so there is no reason to put the private
key into state.

Get the flag wrong and nothing fails here — it fails at `tofu apply`, when
Dataform can't reach the repo. Re-generating is the fix.

## Does this domain need `--unstructured`?

Yes if the source data is **files** — JSON, video, audio, images — that land in
GCS and get read through a BigLake object table, or if it calls Gemini from
BigQuery. That brings in `infra/storage.tf`, `infra/seed.tf`, `scripts/` and
`data/`.

No if the source is already a BigQuery table (a public dataset, an existing
table, something loaded by another process). Omit the flag and those files are
removed along with the API entries, variables and outputs that only existed for
them.

Getting this wrong isn't fatal — re-generate, or copy the files back from the
template.

## After `init.sh`

1. **Push to `main` first.** The Dataform repo pulls from GitHub at apply time,
   so the code has to exist on `main` before `tofu apply` — not after.
2. **Create the GCP project and link billing.** One-time, manual, deliberately
   not automated:
   ```bash
   gcloud projects create <project> --organization=<org-id>
   gcloud billing projects link <project> --billing-account=<billing-id>
   ```
3. `./infra/scripts/setup.sh` — enables the bootstrap APIs, issues the deploy
   key if this repo is private, creates the versioned state bucket, and runs
   `tofu init` against it.
4. `cd infra && tofu apply`

## Verify before writing any SQL

The template ships an `example_*` pipeline over `bigquery-public-data`. It
exists so the **infrastructure proves itself first**: state bucket, API
enablement, runner service account under strict act-as, the Dataform repo, the
pipeline trigger, and the assertions dataset. Expect:

```
pipeline SUCCEEDED
SELECT * FROM `assertions.example_top_words_integrity`;  -- empty = pass
SELECT * FROM `serving.example_top_words` LIMIT 10;      -- rows
```

If that's green, the scaffolding works and anything that breaks next is your
SQL. Only then start replacing `example_*` with real definitions.
